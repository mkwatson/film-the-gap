# Sponsor product opportunity atlas

Research snapshot: **2026-08-26 PT**. This is an expansive opportunity inventory, not a shortlist or a stack decision. It intentionally preserves competing product and architecture branches until small end-to-end experiments give us evidence to converge.

The official challenge supporters represented here are OpenAI, Google Chrome, Cloudflare, Vercel, Netlify, Shopify, and Render. MCP-B is recorded separately because its creator is a judge and it is directly relevant to WebMCP, but it is not mislabeled as a challenge sponsor.

## Why this atlas exists

The sponsor products are not merely implementation choices. Together they now cover most of a new agentic-web stack:

```text
human + agent client
  ChatGPT Browser / Chrome / voice / on-device AI
                    |
page-native capabilities and shared live state
  WebMCP / Shopify storefront tools / MCP-B interop
                    |
durable agents, code, retrieval, media, and workflows
  OpenAI / Cloudflare / Vercel / Netlify / Render
                    |
identity, negotiation, payment, and transaction state
  UCP / Shopify / OpenAI commerce / Cloudflare payments
                    |
evidence, proof, tracing, security, and evaluation
  provenance / Lean / browser evals / agent observability
```

A deep use of a represented product can make an expert judge an informed advocate for the entry. Several deep, orthogonal sponsor products can compound that advantage when they form one user-to-outcome chain. The [portfolio rule](STRATEGY.md#sponsor-product-portfolio-objective) is to maximize positive marginal sponsor-product value, not minimize integrations or collect logos. We should eventually choose one coherent primary host; during discovery, keeping Cloudflare, Vercel, Netlify, and Render branches alive is cheap and prevents architecture from silently choosing the idea for us.

## Status vocabulary

| Marker     | Meaning for this project                                                                                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NOW**    | Documented as generally usable today; still requires an account, runtime, quota, and end-to-end test.                                                                                  |
| **BETA**   | Public preview, beta, or origin trial. It may be used behind a tested fallback and cannot be our only route to a complete demo.                                                        |
| **GATED**  | Private preview, partner program, waitlist, trust tier, paid-plan gate, or otherwise uncertain access. Preserve the branch; do not put it on the critical path until access is proven. |
| **COMING** | Announced but not currently available. Narrative or future-rung material only.                                                                                                         |
| **BUILD**  | Primarily improves how we build, test, deploy, or operate. Useful evidence of execution, but not automatically a judge-visible product feature.                                        |
| **HERO**   | Can be visible and intelligible in the judged product or three-minute demo.                                                                                                            |

“NOW” never means “assume compatible.” The exact ChatGPT browser, Chrome build, package version, account entitlements, and deployed behavior remain the acceptance test.

## Protocol boundary map

Several current products reuse the same acronyms while solving different layers. The demo and README must stay precise.

| Protocol or artifact                                                                           | What it owns                                                                                                                              | What it does **not** own                                                                           | Potential composition                                                                                            |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| [WebMCP](https://webmachinelearning.github.io/webmcp/)                                         | Ephemeral tools belonging to the currently open page, current UI/session, and visible human-agent collaboration                           | Remote server discovery, a general agent runtime, retail commerce semantics, or payment settlement | Page exposes current lot/evidence/approval state; ChatGPT or Chrome invokes it                                   |
| [Model Context Protocol](https://modelcontextprotocol.io/)                                     | Remote/local tools, resources, prompts, transports, auth, and client/server interoperability independent of a particular open page        | The browser's current visual/session state by default                                              | Backend research, UCP servers, build/ops, or continuation after the page closes                                  |

| [OpenAI Agentic Commerce Protocol](https://developers.openai.com/commerce/)                    | OpenAI-oriented product feeds, agentic checkout, delegated payments, promotions, and production commerce integration                      | Shopify/Google UCP by implication                                                                  | Explore a deliberate boundary only if both programs and semantics are available; never assert interchangeability |
| [Machine Payments Protocol and x402](https://developers.cloudflare.com/agents/tools/payments/) | Paying for HTTP resources, pages, data, or MCP tools through `402` challenges and receipts                                                | Retail catalog, cart, fulfillment, returns, or empirical truth                                     | Pay for scarce evidence, expert inspection, proof computation, or agent services around a UCP transaction        |

| MCP-B                                                                                          | Alex Nahas's browser/WebMCP implementation and interoperability ecosystem                                                                 | MCP Bundles (`.mcpb`) packaging                                                                    | Browser fallback, transports, richer MCP features, and cross-client contract testing                             |
| Lean certificate                                                                               | A checked theorem about a formal model, transition, constraint set, or invariant                                                          | Whether a visual or verbal empirical claim is true; whether real-world input matches the model     | Certify that a mandate/action is allowed given explicit facts and assumptions                                    |

One particularly strong thesis is that WebMCP supplies the missing **situated** layer: remote protocols know products, services, and servers, while a page knows what the human is looking at, what is happening now, and which action will visibly change their shared world.

## Research coverage and freshness rule

This pass inventories every challenge-relevant current product family and recent 2026 launch found in the sponsors' official product indexes, editions, documentation, blogs, and changelogs. “All products” remains a living obligation, not a one-time claim: these companies are shipping during the submission week, and a previously peripheral product can become relevant when a concept changes.

1. Recheck each sponsor's product index and changelog daily during concept/architecture work.
2. Re-read the exact first-party integration documentation in the same turn before adding a product.
3. Record version, status, plan/access gate, tested account, compatibility, and fallback in this file or [PLATFORMS.md](PLATFORMS.md).
4. Re-run the exact ChatGPT and Chrome acceptance matrix after every material page-tool change.
5. Recheck all program gates, pricing, policies, and preview status before recording the demo or making submission claims.
